# M2 approved reference snapshot (DR-0021 option A)

`REFERENCE_SNAPSHOT.json.gz` holds every reference-derived value of the M2 Proof and of the
GMAT M2 evaluation, recorded from a clean, reviewed implementation. The Proof, `gmat_m2.py
compare` and `run` verify their freshly computed references against it, value by value
(`tars.validation.reference_snapshot`). The coverage inventory, the exclusions, the
tolerance method and the measurements are in VAL-0015 (`docs/science/validation.md`).

Baseline 3 (current): 48,310 records, 982,324 values. Against baseline 2 it adds the 31
exact `dop853.marks` records (the reference's mark times), so that `verify-baseline` can
enumerate node crossings independently (review M2-T6 F55); every common value is
bit-identical. Baseline 2 had added the pinned inputs of the sim-seeded and closed-form
values (F53).

Approval evidence: `verify-baseline` passed both while generating and standalone, against
a separate fresh recording of the reviewed code. It checks:
- the inventory: records, counters, entrypoints and part schemas;
- the inputs, bit-identical to the fresh recording;
- every output part, recomputed independently of the runtime references by a
  universal-variable Kepler, LSODA and re-derived scenario values;
- node crossings, enumerated independently;
- DOP853 against the committed GMAT rows (at most 4.66e-6 m and 5.39e-9 m/s);
- the invariants.

Agreement with this file is not evidence of physical correctness; that rests on those
checks.

## Changing the baseline (DR-0021 condition 3)
Never regenerated by tests, CI or the Proof. A new baseline is one reviewed change that:
1. generates a candidate from a clean tree:
   `uv run python toolbox/scripts/reference_snapshot.py generate --out runs/refsnap/candidate.json.gz`
   (it refuses to write this directory, and fails unless the Proof, the GMAT evaluations and
   `verify-baseline` pass);
2. verifies the candidate file standalone (a separate fresh recording):
   `uv run python toolbox/scripts/reference_snapshot.py verify-baseline <candidate>`;
3. compares it with this baseline:
   `uv run python toolbox/scripts/reference_snapshot.py compare <this file> <candidate>`;
4. copies it here, sets `APPROVED_REFERENCE_SNAPSHOT_SHA256`, adds a row above, and records
   the justification and the comparison in the commit message and the review record;
5. passes an independent (Codex) review before it is accepted.
